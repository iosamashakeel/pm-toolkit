# Retrospective

A short, honest review at the end of a sprint or project phase: what
worked, what did not, and what you will actually change next time.
Run it within a day or two of the sprint ending, while memories are
still fresh. No blame, no status reporting — the goal is one or two
real improvements, not a long list nobody follows up.

## Ground rules

Read these out at the start, every time:

- We discuss the work and the process, not people.
- What is said here stays in the room, unless the group agrees to share it.
- Everyone speaks. Silence is not agreement.
- We leave with actions, not just observations.

## Action items

Keep this list short. Three actions with owners beat ten actions
with nobody responsible.

| # | Action | Owner | Due date | Status |
|---|---|---|---|---|
| A1 | _e.g. Agree a cut-off day for design changes_ | | | ☐ Open |
| A2 | | | | ☐ Open |
| A3 | | | | ☐ Open |

Rules for good retrospective actions:

- **One owner per action.** Shared ownership means no ownership.
- **A date, not "soon".** Review open actions at the start of the next
  retrospective — an action carried over twice gets dropped or
  re-scoped, not quietly forgotten.
- **Small enough to finish in one sprint.** If it takes longer, split it.

---

**How to use this template**

1. Before the session, fill in the sprint facts and send the template
   to the team so everyone arrives with examples, not just opinions.
2. Run the session in this order: facts, what went well, what did not
   go well, ideas to try, then actions. Timebox each section.
3. End by reading the action list back out loud, with an owner and a
   date for each item. If nobody owns it, it is not an action.
4. Paste the actions into your tracker (see `status-report.md` in this
   repo) and open the next retrospective with them — that is how the
   team learns the retrospective actually changes things.
5. For sprint planning, pair this with `sprint-planning.md`:
   the retrospective's actions feed directly into the next sprint's
   plan, so improvements are scheduled work, not good intentions.
