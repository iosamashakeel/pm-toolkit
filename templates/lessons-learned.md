# Lessons Learned

Capture what a project actually taught you, while it is still fresh
enough to be useful to the next project. A lessons-learned document
written months later from memory is guesswork; one written at the
end of each phase, with real examples, saves the next team from
repeating the same mistakes and losing the same good ideas.

Write this at the end of a project, or at the end of a major phase
for a long project. It is not a blame report and not a success story.
The test for every entry: could someone starting a similar project
tomorrow do something differently because they read it?

## How to use this template

- Collect input before the review meeting: ask each team member for
  one thing that went well and one that did not, in writing.
- Keep the meeting to 60 minutes. Read the inputs out, group them,
  and agree the changes, not just the observations.
- Share the finished document with the next project's team and with
  your PM community. A lessons-learned file nobody reads is filing,
  not learning.
- Revisit it at the next kick-off: check the previous project's
  action list before you plan the new one.
