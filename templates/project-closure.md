# Project Closure Template

Use this template to close a project properly: confirm the work is done,
hand over what needs handing over, release the team, and record what the
project actually delivered against what it promised. A project is not
finished when the last task is done — it is finished when it is closed.

## 4. Open items and handover

open item needs an owner and a date — "someone will handle it" is not a
plan.

## 5. What went well — keep doing it

- _e.g. Weekly demo on Fridays kept the client close to the work._
- _e.g. The shared risk register caught the hosting delay early._

## 6. What to do differently next time

- _e.g. Agree the review process and turnaround time before work starts._
- _e.g. Budget a buffer week for client feedback rounds._

> 💡 Copy the two lists above into the lessons-learned log so the next
> project starts from them, not from memory.
